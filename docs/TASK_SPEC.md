# 原始任务说明（用户提供，原文保留）

请实现一个可复现的课程项目：GLIGEN 与 MIGC 的多对象可控图像生成比较。

先检查工作目录、AGENTS.md、现有环境和 GPU，再按阶段实现。不要只给方案；实际完成代码与可运行验证。不得虚构结果，未运行的实验必须明确标记。

### 1 项目目标

比较两种原模型如何结合对象描述与位置框，分析对象遗漏、位置错误、颜色串扰，并在保持 GLIGEN 架构不变的情况下尝试局部微调。

完成以下内容：
- 原模型架构与关键组件分析。
- 两种方法的实际生成和自动评测。
- GLIGEN 局部微调对比。
- 超参数、失败案例、质量与计算成本分析。

### 2 官方实现

优先使用并核对官方代码：
- GLIGEN：https://github.com/gligen/GLIGEN
- MIGC：https://github.com/limuloo/MIGC
- Benchmark：https://github.com/LeyRio/MIG_Bench

记录仓库 commit、检查点、依赖版本。不要猜测数据字段或 API。MIGC 使用公开预训练权重推理；GLIGEN 适配官方训练流程。

### 3 建议工程结构

```
project/

  configs/          # 推理、训练、评测配置
  adapters/         # 两种原模型的接口包装

  training/         # GLIGEN 微调

```

按实际需要调整，避免过度封装。两个模型依赖冲突时使用独立环境。

### 4 数据与原模型实验

使用 COCO-MIG：
- 先用 10 个布局验证流程。
- 正式测试采用约 50–100 个布局，每个布局两个固定种子。
- 覆盖不同对象数量，标记同类不同颜色及框重叠程度。
- 单独保留验证布局选择超参数，测试集不参与选择。
- 保存固定样本清单，所有方法使用相同输入。

统一输入包括 sample_id、整体描述、对象描述、归一化框坐标和种子。

优先匹配两种检查点支持的同一 SD 基座。统一可兼容的分辨率、采样步数等配置；不能统一的差异明确记录。

每次生成保存图片、输入、检查点、完整配置、耗时及峰值显存。

### 5 GLIGEN 微调

从同一个预训练检查点分别启动：
- G0：原版，不更新。
- G1：只更新 position_net。
- G2：更新 position_net＋fuser。

保留模型架构和其他模块权重，使用官方扩散去噪目标。不要重新初始化已有控制模块。

训练数据从 COCO 训练集准备小规模带框图片，包含整体描述、对象描述和框坐标。属性描述必须与真实图片一致；只有类别标签时，不能声称提供了颜色监督。训练、验证和测试来源隔离。

实现：
- 参数冻结与优化器参数选择。
- 可训练参数名称和数量记录。
- 训练日志、检查点保存、断点恢复。
- 验证样例生成。
- 检查目标权重更新、冻结权重不变。
- 保留传回可训练模块所需的梯度路径。

G1、G2 使用相同数据、有效 batch size 和更新步数。先短训练，再决定正式预算。

### 6 自动评测

不组织正式人工评分，采用：

对象与位置：
- Grounding DINO 检测对象。
- 统计对象出现率、位置匹配成功率和框 IoU。

颜色绑定：
- 使用 SAM 分割检测对象。
- 在对象 mask 内统计 HSV 目标颜色比例。
- 优先沿用官方颜色范围、阈值和匹配规则。
- 输出位置与颜色联合成功率。

画面质量：
- 使用预训练 CLIP-IQA 自动评分，作为辅助质量指标。
- 与任务正确性分别报告，不能将质量分当作颜色绑定或语义正确性的证明。

注意：
- 官方 COCO-MIG mIoU 会对颜色错误对象作零分处理；另报纯定位 IoU，并明确区分。
- 官方匹配规则与新增的一对一匹配诊断分别命名。
- 保存检测框、mask、颜色比例和失败状态。
- 检测或分割异常不能静默删除，记录异常数量和处理方式。
- 缓存中间结果，避免重复检测和分割。

### 7 架构与实验分析

生成 architecture_analysis.md，说明：

GLIGEN：
- 对象语义与位置编码。
- position_net 的输入和输出。
- fuser 的门控自注意力。
- 与原 U-Net、文本 cross-attention 的连接。
- 不同去噪阶段的 grounding 控制。

MIGC：
- 对象级描述和区域 mask。
- Enhancement Attention。
- Layout Attention。
- SAC 对对象、背景及布局特征的聚合。

注明源码位置、关键张量维度、设计目的与局限。维度从代码或真实前向检查确认，提供两张简化结构图及方法差异表。

超参数实验限定为：
- 验证集上三个 grounding 控制持续比例。
- G2 的两个学习率。
- 同一训练过程的早期与后期检查点。

输出总体结果、按对象数量与框重叠程度的分组指标、训练曲线和至少六组配对图片。分析失败原因时区分观察与推测；不能把更多可训练参数带来的改善直接称为模块协同。

### 8 资源与执行顺序

目标资源：单卡 NVIDIA A40，约 46 GB 显存。
学校任务限制：单次最长 6 小时；主机内存限制需另外核对，不能与显存混淆。

阶段 A：跑通两个模型各自的真实样例，再完成 10 个布局和 50–100 步短训练。测量生成速度、完整训练更新步耗时与显存。

阶段 B：完成原模型批量生成、自动评测及架构分析，形成两方法对照。

阶段 C：完成 G1、G2 和小范围超参数实验。训练从每次约 2,000 更新步的候选预算开始，根据预跑调整；该步数不代表保证收敛。

阶段 D：汇总图表、失败案例和报告材料。

正式长任务必须先有耗时估算。SLURM 作业按约 5 小时一段设计，支持恢复；生成和评测支持跳过已完成样本。生成、检测、分割及质量模型可顺序加载，避免同时占满显存。
